## I/O 系统概述

<AccordionGroup>
  <Accordion title="I/O 系统的组成">
    I/O 系统由**软件**和**硬件**两部分组成。

    | 组成 | 主要内容 | 作用 |
    | --- | --- | --- |
    | I/O 软件 | 驱动程序、I/O 管理程序、中断处理程序 | 控制和管理输入输出操作 |
    | I/O 硬件 | 外部设备、设备控制器 / I/O 接口、总线、DMA 控制器 | 完成实际的数据传送 |

    <Info>
      复习时把“外设—接口—总线—主存/CPU”看成一条数据通路。三种 I/O 方式的区别，本质上就是这条通路上“谁来控制、谁来搬运”。
    </Info>
  </Accordion>

  <Accordion title="为什么需要 I/O 接口">
    CPU 不能按照自身的工作方式直接控制所有外部设备，需要通过 I/O 接口进行连接和转换。主要原因有四点：

    | 不匹配 | 具体表现 |
    | --- | --- |
    | 速度不匹配 | CPU 速度远高于外部设备 |
    | 时序不匹配 | 不同设备的工作时序不同 |
    | 数据格式不匹配 | 并行 / 串行、数据位数、编码方式可能不同 |
    | 电气特性不匹配 | 信号电平、驱动能力可能不同 |

    <Tip>
      接口的核心作用可以概括为“转换 + 缓冲 + 联络”：把外设的“语言”翻译成总线能接受的“语言”，并在速度差异之间做缓冲。
    </Tip>
  </Accordion>
</AccordionGroup>

## I/O 接口

<AccordionGroup>
  <Accordion title="I/O 接口的基本功能">
    1. 实现主机和外设之间的通信联络与控制。
    2. 进行地址译码和设备选择。
    3. 实现数据缓冲，解决速度不匹配问题。
    4. 实现数据格式转换和电平转换。
    5. 传送控制命令、状态信息和数据信息。

    <Info>
      五条功能可以记成：**联络、选址、缓冲、转换、传三类信息**。
    </Info>
  </Accordion>

  <Accordion title="I/O 接口的基本结构">
    | 组成 | 主要作用 |
    | --- | --- |
    | 数据寄存器 | 暂存 CPU 与外设之间传输的数据 |
    | 状态寄存器 | 反映设备当前状态，如忙、就绪、出错 |
    | 控制寄存器 | 接收 CPU 发出的控制命令 |
    | I/O 控制逻辑 | 控制接口内部各部分协调工作 |
    | 地址译码电路 | 根据地址选择对应的 I/O 设备或端口 |

    三个寄存器是选择题的高频辨析点：

    | 寄存器 | 存放内容 | CPU 的典型操作 |
    | --- | --- | --- |
    | 数据寄存器 | 待传送的数据 | 读 / 写数据 |
    | 状态寄存器 | 设备状态（忙、就绪、错误） | 读取状态 |
    | 控制寄存器 | CPU 下发的控制命令 | 写入命令 |

    <Warning>
      数据寄存器不负责“判断设备是否准备好”，状态寄存器也不负责“保存数据”。题目常把三者功能对调来设置干扰项。
    </Warning>
  </Accordion>

  <Accordion title="示例：CPU 向打印机输出数据">
    <Steps>
      <Step title="查状态">
        CPU 读取状态寄存器，判断打印机是否就绪。
      </Step>
      <Step title="发命令">
        CPU 向控制寄存器写入输出命令，启动打印机。
      </Step>
      <Step title="送数据">
        CPU 将数据写入数据寄存器。
      </Step>
      <Step title="接口转发">
        接口把数据传送给打印机，并在完成后更新状态。
      </Step>
    </Steps>

    <Note>
      实际接口中，命令和数据的写入顺序可能不同，有的接口还让命令与数据共用一个端口，靠控制信号区分。这里只表示典型的“查状态—发命令—送数据”顺序。
    </Note>
  </Accordion>

  <Accordion title="I/O 接口的分类">
    | 分类依据 | 类型 |
    | --- | --- |
    | 数据传送方式 | 并行接口、串行接口 |
    | 功能选择灵活性 | 可编程接口、不可编程接口 |
    | 通用性 | 通用接口、专用接口 |
    | 数据传送控制方式 | 程序查询接口、中断接口、DMA 接口 |

    <Info>
      最后一种分类与本章主线直接对应：接口采用哪种控制方式，I/O 系统就呈现哪种数据传送方式。
    </Info>
  </Accordion>

  <Accordion title="I/O 接口与 I/O 端口的区别">
    | 对比 | I/O 接口 | I/O 端口 |
    | --- | --- | --- |
    | 范围 | 主机与外设之间的整个硬件连接和控制部件 | 接口中可以被 CPU 直接访问的寄存器 |
    | 关系 | 整体 | 接口的一部分 |
    | 数量 | 一个接口通常包含多个端口 | 数据端口、状态端口、控制端口等 |

    <Info>
      记忆：**接口是整体，端口是窗口**。CPU 通过端口访问接口，而不是直接访问接口内部的所有电路。
    </Info>
  </Accordion>
</AccordionGroup>

## I/O 端口的编址方式

编址方式解决的是“CPU 如何找到某个端口”的问题，分为统一编址和独立编址两种。

<AccordionGroup>
  <Accordion title="统一编址（存储器映射方式）">
    把 I/O 端口与主存单元放在同一个地址空间中统一编址。

    特点：

    - I/O 端口占用主存地址空间。
    - 可以使用普通的访存指令访问 I/O 端口。
    - 不需要专门的 I/O 指令，指令系统设计相对简单。
    - 可以借用访存指令丰富的寻址方式。
    - 会占用一部分主存地址空间，地址译码相对复杂。

    <Warning>
      统一编址只是“地址空间统一”，端口仍然在接口中，并不是把外设当成主存的一段。做题时不要理解为“外设就是主存”。
    </Warning>
  </Accordion>

  <Accordion title="独立编址（I/O 映射方式）">
    I/O 端口地址空间与主存地址空间相互独立。

    特点：

    - I/O 端口不占用主存地址空间。
    - 使用专门的 I/O 指令访问端口，例如 `IN`、`OUT`。
    - 需要专门的 I/O 控制信号来区分访存和访问端口。
    - I/O 地址位数通常较少，译码相对简单。
    - 指令系统中需要增加 I/O 指令。

    <Note>
      独立编址的端口地址空间可以比主存小得多，这也是它译码简单的原因之一。
    </Note>
  </Accordion>

  <Accordion title="两种编址方式对比">
    | 比较项目 | 统一编址 | 独立编址 |
    | --- | --- | --- |
    | 地址空间 | 与主存统一 | 相互独立 |
    | 是否占用主存地址 | 是 | 否 |
    | 访问指令 | 普通访存指令 | 专用 I/O 指令 |
    | 访问控制信号 | 访存控制信号 | 专用 I/O 控制信号 |
    | 地址译码 | 相对复杂 | 相对简单 |
    | 寻址方式 | 可沿用访存的多种寻址方式 | 通常较简单 |

    <Tip>
      记忆：**统一编址用访存指令，独立编址用 I/O 指令**。看到 `IN` / `OUT` 就选独立编址。
    </Tip>
  </Accordion>
</AccordionGroup>

## 程序查询方式

程序查询方式又称程序轮询方式：CPU 不断查询外设的状态，判断设备是否准备好；未准备好就继续等待，准备好后由 CPU 执行数据传送。

<AccordionGroup>
  <Accordion title="工作过程">
    以外设向 CPU 输入数据为例：

    <Steps>
      <Step title="启动设备">
        CPU 向 I/O 接口发送启动命令。
      </Step>
      <Step title="读取状态">
        CPU 读取状态寄存器。
      </Step>
      <Step title="判断就绪">
        根据状态位判断设备是否准备好。
      </Step>
      <Step title="继续查询">
        如果未就绪，返回继续查询状态。
      </Step>
      <Step title="传送数据">
        如果已就绪，CPU 读取数据寄存器。
      </Step>
      <Step title="写入目的地">
        将数据传送到 CPU 寄存器或主存。
      </Step>
      <Step title="判断结束">
        判断是否传送完成，未完成则继续。
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="特点">
    - CPU 全程参与数据传送。
    - CPU 需要不断查询设备状态。
    - CPU 与外设串行工作，查询期间 CPU 不能执行其他程序。
    - 实现简单，硬件开销小。
    - CPU 利用率低，实时性取决于查询频率。

    <Info>
      程序查询方式的“简单”是硬件和逻辑简单，代价是把等待时间全部压在 CPU 上。
    </Info>
  </Accordion>

  <Accordion title="独占查询与定时查询">
    | 方式 | 做法 | 优点 | 缺点 |
    | --- | --- | --- | --- |
    | 独占查询 | 启动设备后不断查询，直到传送完成 | 响应快，不会错过就绪时刻 | 长期占用 CPU |
    | 定时查询 | 每隔一定时间查询一次设备状态 | 减少查询频率，CPU 可处理其他任务 | 可能增加等待时间，甚至错过设备就绪时机 |

    <Warning>
      定时查询并没有让 CPU 与外设并行搬运数据，它只是降低了“查询”的频率；数据传送仍然由 CPU 完成。
    </Warning>
  </Accordion>
</AccordionGroup>

## 程序中断方式

程序中断方式是指：当外设准备好数据或需要 CPU 处理时，向 CPU 发出中断请求；CPU 在满足响应条件时暂停当前程序，转去执行中断服务程序，处理完毕后返回原程序继续执行。

核心思想：CPU 不必一直等待外设，在外设准备数据期间可以执行其他程序。

<Note>
  CPU 内部的异常与中断机制（中断周期、断点保存等）已在[第 6 章 中央处理器](/computer-architecture/knowledge-summary/chapter-6)整理，本节侧重 I/O 中断方式的数据传送过程。
</Note>

<AccordionGroup>
  <Accordion title="中断的基本过程">
    以外设输入数据为例：

    ```mermaid
    graph TD
      A["外设准备好数据"] --> B["向 CPU 发出中断请求"]
      B --> C{"当前指令结束且允许响应?"}
      C -- "否" --> D["暂不响应，继续执行原程序"]
      D --> C
      C -- "是" --> E["关中断、保存断点"]
      E --> F["引出中断服务程序"]
      F --> G["保护现场"]
      G --> H["执行中断服务程序，完成数据传送等任务"]
      H --> I["恢复现场"]
      I --> J["中断返回，回到断点继续执行"]
    ```

    <Note>
      **中断响应**是 CPU 决定接受中断请求并完成响应操作；**中断处理**是执行具体的中断服务程序。两者不是同一个概念。
    </Note>
  </Accordion>

  <Accordion title="CPU 响应中断的条件">
    通常需要同时满足：

    1. CPU 处于开中断状态，中断允许触发器为 1。
    2. 有外部中断请求。
    3. 对应设备接口的中断允许触发器为 1（针对可屏蔽中断）。
    4. 当前指令执行结束，且满足中断优先级等响应条件。

    <Warning>
      CPU 通常在一条指令执行结束后响应可屏蔽的外部中断，而不是在指令执行过程中随时响应。选项中“执行到任意微操作都可响应”一类说法通常是错的。
    </Warning>
  </Accordion>

  <Accordion title="中断隐指令">
    中断隐指令是 CPU 在响应中断时由**硬件自动完成**的操作，不是普通指令，也不由程序员直接编写。

    主要完成三件事：

    1. **关中断**：防止响应过程被新的中断打断（是否关中断及何时开中断，取决于中断嵌套策略）。
    2. **保存断点**：保存当前程序下一条待执行指令的地址。
    3. **引出中断服务程序**：根据中断向量找到对应的中断服务程序入口地址。

    <Warning>
      保存断点保存的是**下一条待执行指令的地址**（通常是 PC 的值），不是当前正在执行指令的地址。
    </Warning>

    <Info>
      易混：**中断向量地址**是存放中断向量的内存单元地址；**中断向量**是中断服务程序的入口地址（或入口地址的指针）。题目问“根据什么找到入口”时，要看清问的是向量还是向量地址。
    </Info>
  </Accordion>

  <Accordion title="中断服务程序的处理过程">
    1. 保护现场：保存通用寄存器、状态寄存器等信息。
    2. 开中断（如果允许中断嵌套）。
    3. 执行中断服务程序主体，完成数据传送等任务。
    4. 关中断，准备恢复现场。
    5. 恢复现场。
    6. 开中断并执行中断返回指令。

    <Note>
      开中断、关中断的具体时机依体系结构而定。单重中断通常在整个服务过程中不开放中断；多重中断则在保护现场后开中断。
    </Note>
  </Accordion>

  <Accordion title="中断隐指令与中断服务程序的区分">
    | 中断隐指令 | 中断服务程序 |
    | --- | --- |
    | 硬件自动完成 | 软件执行 |
    | 关中断 | 保护现场 |
    | 保存断点 | 处理中断事件 |
    | 引出中断服务程序 | 恢复现场、返回 |

    <Tip>
      记忆：**隐指令做“入口三件事”，服务程序做“现场与业务”**。
    </Tip>
  </Accordion>

  <Accordion title="多重中断与中断嵌套">
    **多重中断**：CPU 在处理中断的过程中，又有新的中断请求到来。

    **中断嵌套**：CPU 允许更高优先级的中断打断当前正在执行的中断服务程序。

    典型执行顺序：

    ```text
    主程序
      → 低优先级中断服务程序
        → 高优先级中断服务程序
        → 返回低优先级中断服务程序
      → 返回主程序
    ```

    <Info>
      高优先级中断可以打断低优先级中断；低优先级中断不能打断高优先级中断。实现中断嵌套通常需要在服务程序中提前开中断。
    </Info>
  </Accordion>

  <Accordion title="中断屏蔽字">
    中断屏蔽字用于控制 CPU 是否允许响应某些中断请求。通常约定：

    - 屏蔽位为 1：屏蔽该中断。
    - 屏蔽位为 0：允许该中断。

    设中断优先级为 A > B > C > D，采用“处理某中断时屏蔽自身及更低优先级”的规则，则屏蔽字可以写成：

    | 正在处理的中断 | 屏蔽字（A B C D） | 效果 |
    | --- | --- | --- |
    | A | 1 1 1 1 | 屏蔽所有中断 |
    | B | 0 1 1 1 | 允许 A，屏蔽 B、C、D |
    | C | 0 0 1 1 | 允许 A、B，屏蔽 C、D |
    | D | 0 0 0 1 | 允许 A、B、C，屏蔽 D |

    <Warning>
      在该约定下，屏蔽字中 1 的个数越多，对应的处理优先级越高。但不同教材或题目的位序、极性可能不同，做题时先看题目说明。
    </Warning>

    <Info>
      注意区分：**中断优先级**决定多个请求同时到来时谁先被响应；**屏蔽字**决定当前正在处理中断时，哪些请求还能被响应。修改屏蔽字可以动态改变中断处理优先级。
    </Info>
  </Accordion>
</AccordionGroup>

## DMA 方式

DMA（直接存储器存取）是一种由 DMA 控制器直接控制外设与主存之间数据传送的方式。

核心思想：数据传送不再需要 CPU 逐个参与，而由 DMA 控制器接管总线，直接完成外设与主存之间的数据交换。

以磁盘向主存传送一大块数据为例：

| 方式 | 数据由谁搬运 | CPU 的主要工作 |
| --- | --- | --- |
| 程序查询 | CPU | 不断查询并搬运每个数据 |
| 程序中断 | CPU | 每次设备就绪后响应中断并搬运数据 |
| DMA | DMA 控制器 | 初始化和传送结束后的处理 |

<AccordionGroup>
  <Accordion title="DMA 控制器的组成">
    | 组成 | 作用 |
    | --- | --- |
    | 主存地址计数器 AR | 存放主存中待传送数据的地址 |
    | 字计数器 WC | 记录剩余传送的数据字数 |
    | 数据缓冲寄存器 DR | 暂存传送的数据 |
    | DMA 控制逻辑 | 控制整个 DMA 传送过程 |
    | 设备地址寄存器 | 存放外设设备地址 |
    | 状态控制寄存器 | 保存传送方向、状态等信息 |

    其中最关键的是 AR 和 WC：

    - 每传送一个数据字，AR 自动加 1（或按字长递增）。
    - 每传送一个数据字，WC 自动减 1。
    - WC 减到 0，表示本次 DMA 传送完成。

    <Info>
      把 DMA 控制器理解成一个“小 CPU”：它有地址、计数、缓冲和控制逻辑，只是功能专一，只负责搬数据。
    </Info>
  </Accordion>

  <Accordion title="DMA 传送过程">
    DMA 传送一般分为三个阶段：

    <Steps>
      <Step title="预处理阶段（CPU 完成）">
        CPU 向 DMA 控制器发送启动命令，设置传送方向、主存起始地址和传送数据数量，初始化 DMA 控制器的相关寄存器。
      </Step>
      <Step title="数据传送阶段（DMA 控制器完成）">
        外设向 DMA 控制器提出 DMA 请求；DMA 控制器向 CPU 请求总线使用权；CPU 让出总线后，DMA 控制器控制总线完成外设与主存之间的数据传送，并更新 AR 和 WC，判断是否传送完成。
      </Step>
      <Step title="后处理阶段（CPU 完成）">
        DMA 控制器在传送结束后向 CPU 发送中断请求；CPU 响应中断，检查数据传送是否正确，并进行必要的后续处理。
      </Step>
    </Steps>

    <Warning>
      DMA 的数据传送阶段不需要 CPU 逐个参与，但**预处理和后处理仍然需要 CPU**。“DMA 完全不需要 CPU”是常见错误说法。
    </Warning>
  </Accordion>

  <Accordion title="DMA 的三种传送方式">
    **（1）停止 CPU 访问主存**

    DMA 控制器获得总线控制权后，停止 CPU 访问主存。

    - DMA 独占主存访问权。
    - CPU 在此期间不能访问主存。
    - DMA 传送效率高，但 CPU 等待时间较长。
    - 适合高速设备的大块数据传送。

    **（2）周期挪用（周期窃取）**

    当 DMA 需要访问主存时，向 CPU 申请总线控制权，窃取一个或几个主存周期。

    - DMA 需要访存时才占用主存周期。
    - CPU 在 DMA 访问主存期间暂停访存，DMA 完成后继续。
    - 对 CPU 的影响相对较小。
    - 每次传送都要申请总线，控制稍复杂。

    **（3）DMA 与 CPU 交替访问主存**

    将一个 CPU 工作周期分成若干时间片，DMA 和 CPU 分别在不同时间片访问主存。

    - CPU 和 DMA 交替访问主存。
    - 不需要完全停止 CPU 工作，通常也不需要总线申请。
    - 提高主存利用率。
    - 适用于 CPU 工作周期比主存存取周期长的情况。
    - 硬件控制相对复杂。
  </Accordion>

  <Accordion title="三种 DMA 传送方式对比">
    | 方式 | 主存使用权 | CPU 是否停止访存 | 特点 |
    | --- | --- | --- | --- |
    | 停止 CPU 访问主存 | DMA 独占 | 整个传送期间停止 | 效率高，CPU 等待时间长 |
    | 周期挪用 | DMA 按需占用 | 仅在被占用的主存周期 | 影响较小，需要总线申请 |
    | DMA 与 CPU 交替访问 | 按时间片分配 | 不在自身时间片时等待 | 无需总线申请，控制复杂 |

    <Tip>
      记忆：**停止是“全让”，周期挪用是“按需让”，交替访问是“分时用”**。
    </Tip>
  </Accordion>

  <Accordion title="DMA 与中断方式的区别">
    | 比较项目 | 中断方式 | DMA 方式 |
    | --- | --- | --- |
    | 数据传送主体 | CPU | DMA 控制器 |
    | CPU 介入程度 | 较高 | 较低 |
    | 传送过程是否打断程序 | 是，切换去执行服务程序 | 通常不打断程序执行，仅可能与 CPU 争总线或主存 |
    | 是否需要保存现场 | 需要 | 传送过程中不需要 |
    | 中断请求的作用 | 请求 CPU 处理 | 传送结束时通知 CPU |
    | 中断发生时机 | 数据准备好或需要处理时 | 一批数据传送完成时 |
    | 数据传送单位 | 通常以字或字节为单位 | 通常以数据块为单位 |
    | 适用场景 | 低速或需要 CPU 处理的设备 | 高速、大批量数据传送 |

    <Warning>
      最容易考的区别：中断方式下数据传送仍然需要 CPU 参与；DMA 方式下数据直接在外设和主存之间传送，CPU 不参与具体的数据搬运。
    </Warning>
  </Accordion>

  <Accordion title="DMA 与中断的联系">
    二者都可以让 CPU 与外设并行工作，但实现方式不同。

    - 中断：设备请求 CPU 处理，CPU 负责具体的数据传送。
    - DMA：DMA 控制器负责具体的数据传送，传送完成后再通过中断通知 CPU。

    <Info>
      DMA 的“结束通知”仍然依赖中断机制。所以 DMA 不是取代中断，而是把“搬数据”从 CPU 手中接过去，中断只负责收尾。
    </Info>
  </Accordion>
</AccordionGroup>

## 通道方式（了解）

通道是专门负责 I/O 的处理器，可以执行通道程序，控制多台外设与主存之间的数据传送。CPU 只需发出启动命令，通道完成后通过中断通知 CPU。

| 方式 | CPU 介入程度 | 数据传送控制者 |
| --- | --- | --- |
| 程序查询 | 全程参与 | CPU |
| 程序中断 | 每次数据传送 | CPU |
| DMA | 初始化与后处理 | DMA 控制器 |
| 通道 | 启动与结束处理 | 通道（I/O 处理机） |

<Note>
  通道方式不属于现行 408 这一部分的明确考纲要求，了解“由通道进一步接管 I/O 控制、减轻 CPU 负担”的思想即可，不必展开通道指令和通道程序细节。
</Note>

## 三种 I/O 方式对比

| 比较项目 | 程序查询 | 程序中断 | DMA |
| --- | --- | --- | --- |
| 是否需要 CPU 查询 | 是 | 否 | 否 |
| 数据传送主体 | CPU | CPU | DMA 控制器 |
| CPU 是否参与数据传送 | 是 | 是 | 否 |
| 数据传送单位 | 通常字 / 字节 | 通常字 / 字节 | 数据块 |
| CPU 工作效率 | 低 | 较高 | 高 |
| 适用场景 | 简单低速设备 | 需要及时响应的设备 | 高速大批量设备 |

三种方式的核心发展逻辑：

1. **程序查询**：CPU 一直主动询问设备“准备好了吗”，既负责等待，又负责传送数据。
2. **程序中断**：设备准备好后主动通知 CPU，CPU 可以先执行其他程序，但传送数据时仍需要 CPU。
3. **DMA**：DMA 控制器直接负责数据传送，CPU 只负责初始化和传送完成后的处理。

<Info>
  判断方式时抓住两个问题：**谁在等？谁在搬？** 等和搬都由 CPU 完成是查询；设备叫 CPU、CPU 搬是中断；CPU 只做首尾、控制器搬是 DMA。
</Info>

## 本章常考计算

<AccordionGroup>
  <Accordion title="程序查询方式的 CPU 占用时间">
    若每次查询需要 $t$ 时间，共查询 $n$ 次：

    $$
    T_{\text{查询}} = n t
    $$

    如果还需要数据传送时间，则按题目给出的具体过程累加：

    $$
    T_{\text{总}} = T_{\text{查询}} + T_{\text{传送}}
    $$

    <Warning>
      查询次数不一定等于数据个数。若每次传送前要查询多次，或每次查询可处理多个数据，要按题目条件换算。
    </Warning>
  </Accordion>

  <Accordion title="DMA 传送时间">
    若传送数据量为 $N$ 字节，传输速率为 $R$ 字节/秒：

    $$
    T_{\text{DMA}} = \frac{N}{R}
    $$

    若题目按“每个总线周期传送 $k$ 字节、总线周期为 $T$”给出，则：

    $$
    T_{\text{DMA}} = \frac{N}{k} \times T
    $$

    以上通常只计算数据传送阶段，不含预处理和后处理。

    <Info>
      注意区分：**传输时间**是数据真正传送所需的时间；**CPU 占用时间**是 CPU 实际参与初始化、后处理等操作的时间。两者不一定相等。
    </Info>
  </Accordion>

  <Accordion title="CPU 利用率">
    $$
    \text{CPU 利用率} = \frac{T_{\text{CPU}}}{T_{\text{总}}} \times 100\%
    $$

    其中 $T_{\text{总}}$ 是完成整个 I/O 任务的总时间，$T_{\text{CPU}}$ 是其中 CPU 真正执行指令的时间。

    <Warning>
      不能把数据传输时间全部当成 CPU 占用时间。DMA 方式下，传送期间 CPU 通常可以执行其他程序，只有预处理、后处理和总线冲突才占用 CPU。
    </Warning>
  </Accordion>

  <Accordion title="计算示例：DMA 的 CPU 时间占比">
    某 DMA 方式传送 $4\text{ KB}$ 数据，外设传输速率为 $20\text{ MB/s}$，CPU 主频为 $1\text{ GHz}$，预处理和后处理共需 2000 个时钟周期。求 DMA 传送时间和 CPU 时间占比。

    DMA 传送时间：

    $$
    T_{\text{DMA}} = \frac{4 \times 1024}{20 \times 10^6} = 204.8\ \mu s
    $$

    CPU 用于预处理和后处理的时间：

    $$
    T_{\text{CPU}} = \frac{2000}{1 \times 10^9} = 2\ \mu s
    $$

    CPU 时间占比：

    $$
    \frac{2}{204.8 + 2} \times 100\% \approx 0.97\%
    $$

    <Info>
      这个例子说明：DMA 方式下 CPU 只承担首尾工作，时间占比通常很低，大部分时间可以用于执行其他程序。
    </Info>
  </Accordion>
</AccordionGroup>

## 高频易错点

| 易错知识点 | 正确理解 |
| --- | --- |
| I/O 接口和 I/O 端口 | 接口是整体，端口是可被 CPU 访问的寄存器 |
| 统一编址 | 端口占用主存地址空间，用普通访存指令访问 |
| 独立编址 | 端口地址空间独立，用 `IN` / `OUT` 等专用指令访问 |
| 中断响应时间 | 通常在一条指令执行结束后 |
| 中断隐指令 | 硬件自动完成，不是普通指令 |
| 保存断点 | 保存下一条待执行指令的地址 |
| 中断向量 | 中断向量地址是存放向量的单元地址，不等于服务程序入口地址 |
| 中断服务程序 | 由软件执行，负责保护 / 恢复现场和处理事件 |
| 中断方式搬数据 | CPU 仍然参与数据传送 |
| DMA 方式搬数据 | DMA 控制器直接完成，CPU 不逐个搬运 |
| DMA 周期挪用 | DMA 占用主存周期时，CPU 暂时不能访问主存 |
| DMA 传送结束 | 通常通过中断通知 CPU |
| DMA 全过程 | 预处理和后处理仍然需要 CPU |
| 中断屏蔽字 | 通常 1 表示屏蔽、0 表示允许，具体看题目约定 |

## 本章考前速记

<AccordionGroup>
  <Accordion title="接口与端口">
    - 接口是整体，端口是 CPU 可访问的寄存器。
    - 数据寄存器存数据，状态寄存器存状态，控制寄存器存命令。
    - 接口功能：联络、选址、缓冲、转换、传三类信息。
  </Accordion>

  <Accordion title="端口编址">
    - 统一编址：占主存地址空间，用访存指令。
    - 独立编址：独立地址空间，用 `IN` / `OUT`。
  </Accordion>

  <Accordion title="程序查询">
    - CPU 主动查询，CPU 全程搬运数据。
    - CPU 与外设串行工作，利用率低。
    - 独占查询一直查，定时查询隔一段时间查。
  </Accordion>

  <Accordion title="程序中断">
    - 设备准备好后主动通知 CPU。
    - 响应条件：开中断、有请求、设备允许、指令结束。
    - 隐指令：关中断、保存断点、引出服务程序。
    - 断点是下一条待执行指令的地址。
    - 屏蔽字通常 1 屏蔽、0 允许。
  </Accordion>

  <Accordion title="DMA">
    - DMA 控制器直接搬运数据，CPU 只做预处理和后处理。
    - AR 加、WC 减，WC 为 0 表示完成。
    - 三种方式：停止 CPU 访存、周期挪用、交替访问。
    - 传送结束通常用中断通知 CPU。
  </Accordion>

  <Accordion title="三种方式一句话">
    - 程序查询：CPU 等并搬。
    - 程序中断：设备叫，CPU 搬。
    - DMA：CPU 只做首尾，控制器搬。
  </Accordion>
</AccordionGroup>

  本章核心：接口与端口、两种编址、三种 I/O 方式的流程与区别，以及中断隐指令和 DMA 周期挪用这些高频细节。
</Info>
