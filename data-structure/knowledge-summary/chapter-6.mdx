## 图的基本概念

<AccordionGroup>
  <Accordion title="定义与基本术语">
    **图**由顶点集合 $V$ 和边集合 $E$ 组成：

    $$
    G=(V,E)
    $$

    - $|V|=n$：顶点数
    - $|E|=m$：边数
    - 408 中图不能为空图：$V$ 至少有一个顶点，$E$ 可以为空
    - 线性表、树可以为空，图不可以（按王道定义）

    **无向边**：$(v_i,v_j)$，没有方向，两个顶点可以相互到达。

    **有向边（弧）**：$\langle v_i,v_j\rangle$，从 $v_i$ 指向 $v_j$，不表示反方向也有边。

    <Tabs>
      <Tab title="无向图">
        ```mermaid
        graph LR
          A --- B
          A --- C
          B --- C
          C --- D
        ```

        边没有方向，$(v_i,v_j)$ 与 $(v_j,v_i)$ 是同一条边。
      </Tab>
      <Tab title="有向图">
        ```mermaid
        graph LR
          A --> B
          A --> C
          B --> C
          C --> D
        ```

        弧有方向，$\langle v_i,v_j\rangle$ 与 $\langle v_j,v_i\rangle$ 是两条不同的弧。
      </Tab>
    </Tabs>
  </Accordion>

  <Accordion title="简单图与多重图">
    | 类型 | 特点 |
    | --- | --- |
    | 简单图 | 不存在重复边，也不存在顶点到自身的边（自环） |
    | 多重图 | 允许多条连接相同顶点的边，也允许自环 |

    <Info>
    408 讨论图的基本性质时，通常以**简单图**为基础。本章若未特别说明，默认是简单图。
    </Info>

    **稀疏图与稠密图**：边数相对较少称为稀疏图，边数相对较多称为稠密图。二者没有绝对统一的划分界限，通常结合 $n$ 与 $m$ 的关系判断。
  </Accordion>

  <Accordion title="完全图">
    **无向完全图**：任意两个不同顶点之间都存在一条边。

    $$
    m=\frac{n(n-1)}{2}
    $$

    **有向完全图**：任意两个不同顶点之间都存在方向相反的两条弧。

    $$
    m=n(n-1)
    $$

    | 类型 | 边数 | 特点 |
    | --- | --- | --- |
    | 无向完全图 | $\dfrac{n(n-1)}{2}$ | 每对顶点之间只有一条边 |
    | 有向完全图 | $n(n-1)$ | 每对顶点之间有两条方向相反的弧 |

    <Tip>
    **记忆**：无向完全图是“每对顶点一条边”，有向完全图是“每对顶点两条弧”，所以有向完全图的边数是无向完全图的 2 倍。
    </Tip>
  </Accordion>

  <Accordion title="子图与生成子图">
    设有两个图 $G=(V,E)$ 和 $G'=(V',E')$。

    **子图**：若

    $$
    V'\subseteq V,\qquad E'\subseteq E
    $$

    且 $E'$ 中每条边所关联的顶点都属于 $V'$，则称 $G'$ 是 $G$ 的子图。

    **生成子图**：若子图满足

    $$
    V'=V
    $$

    则称 $G'$ 是 $G$ 的生成子图。

    | 比较项目 | 子图 | 生成子图 |
    | --- | --- | --- |
    | 顶点 | 可以减少 | 必须全部保留 |
    | 边 | 可以减少 | 可以减少 |
    | 顶点集合 | $V'\subseteq V$ | $V'=V$ |
    | 边集合 | $E'\subseteq E$ | $E'\subseteq E$ |

    <Warning>
    生成子图只要求“顶点一个不少”，并不要求连通，也不要求无环；**生成子图不一定是生成树**。只有连通且无环的生成子图才是生成树。
    </Warning>
  </Accordion>

  <Accordion title="顶点的度">
    **无向图**：顶点 $v$ 的度记为 $TD(v)$，表示与 $v$ 相连的边数。

    $$
    \sum_{v\in V}TD(v)=2m
    $$

    原因：每条无向边有两个端点，在度数总和中被计算两次。

    **有向图**：

    - 入度 $ID(v)$：指向 $v$ 的弧数
    - 出度 $OD(v)$：从 $v$ 出发的弧数
    - 总度 $TD(v)=ID(v)+OD(v)$

    $$
    \sum_{v\in V}ID(v)=\sum_{v\in V}OD(v)=m
    $$

    原因：每条有向弧贡献一个入度和一个出度。

    | 图 | 度的定义 | 重要性质 |
    | --- | --- | --- |
    | 无向图 | 与顶点相连的边数 | 度数和 $=2m$ |
    | 有向图 | 入度与出度之和 | 入度和 $=$ 出度和 $=m$ |

    <Tip>
    无向图中度为奇数的顶点个数一定是偶数；这是“度数和为偶数”的直接推论。
    </Tip>
  </Accordion>

  <Accordion title="路径、回路与连通性">
    | 概念 | 含义 |
    | --- | --- |
    | 路径 | 顶点之间经过的边构成的序列 |
    | 路径长度 | 路径中边的数量 |
    | 带权路径长度 | 路径上所有边的权值之和 |
    | 简单路径 | 顶点不重复的路径 |
    | 回路（环） | 起点和终点相同的路径 |
    | 简单回路 | 除起点和终点外，其余顶点不重复 |

    - 无权图中，路径长度通常按经过的边数计算。
    - 带权图中，最短路径通常按权值之和计算。

    **连通（无向图）**：顶点 $v$ 到 $w$ 存在路径。

    **连通图**：无向图中任意两个顶点之间都存在路径。

    **连通分量**：无向图中的**极大连通子图**。

    **强连通（有向图）**：从 $v$ 到 $w$ 存在路径，且从 $w$ 到 $v$ 也存在路径。

    **强连通图**：有向图中任意两个顶点都相互可达。

    **强连通分量**：有向图中的**极大强连通子图**。

    <Info>
    “极大”指不能再加入原图中的其他顶点或边而保持连通（或强连通）。连通图只有一个连通分量；非连通图至少有两个连通分量。
    </Info>

    <Warning>
    有向图一次 DFS 访问到全部顶点，**不能**说明它一定是强连通图；一次遍历只能说明从起点可达其他顶点，不能保证其他顶点都能回到起点。
    </Warning>
  </Accordion>

  <Accordion title="生成树与生成森林">
    **生成树**：连通无向图的生成树是包含全部顶点的**极小连通子图**。

    对 $n$ 个顶点的连通无向图，生成树满足：

    1. 包含全部 $n$ 个顶点
    2. 恰好有 $n-1$ 条边
    3. 连通且不存在回路
    4. 删除任意一条边都会变成非连通图
    5. 增加任意一条边都会产生回路

    $$
    m=n-1
    $$

    **生成森林**：非连通图中，每个连通分量分别取一棵生成树，所有生成树共同构成生成森林。

    | 比较项目 | 生成树 | 生成森林 |
    | --- | --- | --- |
    | 适用对象 | 连通无向图 | 非连通无向图 |
    | 是否包含全部顶点 | 是 | 是 |
    | 是否存在回路 | 不存在 | 不存在 |
    | 连通性 | 整体连通 | 整体不连通 |

    **边数与连通性、回路的关系**（$n$ 个顶点的无向图）：

    - 若 $m<n-1$，一定不连通
    - 若图连通且 $m=n-1$，一定是树
    - 若 $m=n-1$，不一定是树（可能不连通且含环）
    - 若 $m>n-1$，一定存在回路

    <Warning>
    生成树是生成子图，但生成子图不一定是生成树；生成树要求**连通且无环**。一个连通图可以有多棵不同的生成树。
    </Warning>
  </Accordion>
</AccordionGroup>

## 图的存储结构

图的存储结构主要有邻接矩阵、邻接表、十字链表和邻接多重表，其中邻接矩阵和邻接表是重点。

<AccordionGroup>
  <Accordion title="邻接矩阵">
    用二维数组 $A[n][n]$ 存储顶点之间的邻接关系。

    **无权图**：

    - 若 $v_i$ 与 $v_j$ 相邻，$A[i][j]=1$
    - 否则 $A[i][j]=0$

    **带权图**：

    - 若存在边，$A[i][j]=w_{ij}$
    - 否则 $A[i][j]=\infty$

    **无向图**：

    - 矩阵关于主对角线对称
    - 对角线元素通常为 0（简单图无自环）
    - 第 $i$ 行非零元素个数等于顶点 $v_i$ 的度

    **有向图**：

    - 矩阵一般不对称
    - 第 $i$ 行非零元素个数等于 $v_i$ 的出度
    - 第 $i$ 列非零元素个数等于 $v_i$ 的入度

    | 项目 | 复杂度 |
    | --- | --- |
    | 空间复杂度 | $O(n^2)$ |
    | 判断两个顶点是否邻接 | $O(1)$ |
    | 查找某顶点的所有邻接点 | $O(n)$ |
    | 遍历整个图 | $O(n^2)$ |

    <Tip>
    邻接矩阵适合**稠密图**；判断边是否存在很快，但找邻接点和遍历较慢。
    </Tip>
  </Accordion>

  <Accordion title="邻接表">
    邻接表采用“顺序存储顶点表 + 链式存储边表”的方式。

    ```c 邻接表结构
    #define MaxVertexNum 100
    typedef struct ArcNode {
        int adjvex;                 // 邻接点编号
        struct ArcNode *nextarc;    // 下一条边
        int info;                   // 权值等信息
    } ArcNode;

    typedef struct VNode {
        VertexType data;            // 顶点信息
        ArcNode *firstarc;          // 第一条边
    } VNode, AdjList[MaxVertexNum];

    typedef struct {
        AdjList vertices;
        int vexnum, arcnum;
    } ALGraph;
    ```

    **无向图**：一条无向边要在两个顶点的邻接表中各存一次，所以边结点总数为 $2m$。

    **有向图**：通常采用出边邻接表，每条弧存一次，边结点总数为 $m$。

    - 一个顶点的邻接表长度等于该顶点的度（无向图）或出度（有向图）
    - 求有向图入度需要遍历所有边，或额外建立**逆邻接表**
    - 邻接表不唯一，取决于边结点的插入顺序

    | 项目 | 复杂度 |
    | --- | --- |
    | 空间复杂度 | $O(n+m)$ |
    | 查找某顶点的所有邻接点 | $O(d(v))$ |
    | 判断两个顶点是否邻接 | $O(d(v))$ |
    | 遍历整个图 | $O(n+m)$ |

    <Tip>
    邻接表适合**稀疏图**；找邻接点方便，但判断两点是否邻接需要扫描链表。$d(v)$ 表示顶点 $v$ 的度或出度。
    </Tip>
  </Accordion>

  <Accordion title="邻接矩阵与邻接表对比">
    | 比较项目 | 邻接矩阵 | 邻接表 |
    | --- | --- | --- |
    | 存储方式 | 二维数组 | 顶点表 + 边链表 |
    | 空间复杂度 | $O(n^2)$ | $O(n+m)$ |
    | 判断边是否存在 | $O(1)$ | $O(d(v))$ |
    | 查找邻接点 | $O(n)$ | $O(d(v))$ |
    | 适用图 | 稠密图 | 稀疏图 |
    | 无向图存储边 | 矩阵对称 | 每条边存两次 |
    | 有向图存储边 | 矩阵一般不对称 | 每条边存一次 |

    <Check>
    **选择**：边多、需要快速判断邻接关系 → 邻接矩阵；边少、需要快速遍历邻接点 → 邻接表。
    </Check>
  </Accordion>

  <Accordion title="十字链表与邻接多重表">
    **十字链表**：有向图的存储结构，把邻接表和逆邻接表结合起来。

    | 组成 | 含义 |
    | --- | --- |
    | `tailvex` | 弧尾顶点编号 |
    | `headvex` | 弧头顶点编号 |
    | `tlink` | 下一条具有相同弧尾的弧 |
    | `hlink` | 下一条具有相同弧头的弧 |
    | `info` | 弧的相关信息 |

    - 每条有向弧只存一个边结点
    - 既能方便找某个顶点的所有出边，也能方便找所有入边
    - 适合需要同时管理入边和出边的有向图

    **邻接多重表**：无向图的存储结构。

    | 组成 | 含义 |
    | --- | --- |
    | `ivex` | 边的一个顶点 |
    | `jvex` | 边的另一个顶点 |
    | `ilink` | 下一条依附于 `ivex` 的边 |
    | `jlink` | 下一条依附于 `jvex` 的边 |
    | `info` | 边的相关信息 |

    - 每条无向边只存一个边结点
    - 一个边结点同时连接两个顶点
    - 方便进行边的删除和操作

    <Tip>
    **记忆**：十字链表用于**有向图**，邻接多重表用于**无向图**；前者同时管理入边和出边，后者保证每条边只存一次。
    </Tip>
  </Accordion>

  <Accordion title="四种存储结构总结">
    | 存储结构 | 适用图 | 核心特点 |
    | --- | --- | --- |
    | 邻接矩阵 | 有向图、无向图 | 二维数组，判断边快 |
    | 邻接表 | 有向图、无向图 | 链式存储邻接关系，省空间 |
    | 十字链表 | 有向图 | 同时管理入边和出边 |
    | 邻接多重表 | 无向图 | 每条边只存储一次 |

    <Info>
    408 选择题常考“哪种结构适合哪种图”和“边结点数量”。记住：无向邻接表存 $2m$ 个边结点，有向邻接表存 $m$ 个，十字链表存 $m$ 个弧结点，邻接多重表存 $m$ 个边结点。
    </Info>
  </Accordion>
</AccordionGroup>

## 图的遍历

图的遍历从某个顶点出发，按一定规则访问图中每个顶点一次，且每个顶点只访问一次。BFS 逐层扩展，DFS 沿路径深入。

<AccordionGroup>
  <Accordion title="广度优先搜索（BFS）">
    BFS 使用**队列**，从一个顶点开始，先访问所有直接相邻的顶点，再依次访问这些邻接点的邻接点。

    **基本步骤**：

    1. 访问起始顶点，标记为已访问并入队
    2. 队列非空时，取出队头顶点
    3. 找到该顶点所有尚未访问的邻接点
    4. 依次访问、标记并入队
    5. 重复直到队列为空

    ```c BFS
    void BFS(Graph G, int v) {
        visit(v);
        visited[v] = true;
        Enqueue(Q, v);

        while (!isEmpty(Q)) {
            Dequeue(Q, v);
            for (w = FirstNeighbor(G, v);
                 w >= 0;
                 w = NextNeighbor(G, v, w)) {
                if (!visited[w]) {
                    visit(w);
                    visited[w] = true;
                    Enqueue(Q, w);
                }
            }
        }
    }
    ```

    | 存储结构 | 时间复杂度 |
    | --- | --- |
    | 邻接矩阵 | $O(n^2)$ |
    | 邻接表 | $O(n+m)$ |

    **重要性质**：

    1. BFS 使用队列，先进先出
    2. 可以求**无权图**的单源最短路径（按边数计算）
    3. 可以得到 BFS 生成树或生成森林
    4. 遍历序列不一定唯一，取决于起点和邻接点访问次序
    5. 非连通图需要从未访问顶点中重新选择起点

    <Tip>
    在无权图中，BFS 首次到达某顶点时的层数，就是源点到该顶点的最短路径长度。
    </Tip>
  </Accordion>

  <Accordion title="深度优先搜索（DFS）">
    DFS 使用**递归或栈**，从一个顶点开始，沿着一条路径尽可能深入，直到无法继续访问，再回溯搜索其他路径。

    **基本步骤**：

    1. 访问起始顶点，标记为已访问
    2. 找到一个尚未访问的邻接点
    3. 继续向该邻接点深入
    4. 当前顶点没有未访问的邻接点时回溯
    5. 重复直到所有可达顶点都被访问

    ```c DFS
    void DFS(Graph G, int v) {
        visit(v);
        visited[v] = true;

        for (w = FirstNeighbor(G, v);
             w >= 0;
             w = NextNeighbor(G, v, w)) {
            if (!visited[w]) {
                DFS(G, w);
            }
        }
    }
    ```

    | 存储结构 | 时间复杂度 |
    | --- | --- |
    | 邻接矩阵 | $O(n^2)$ |
    | 邻接表 | $O(n+m)$ |

    **重要性质**：

    1. DFS 使用递归或栈，后进先出
    2. 可以得到 DFS 生成树或生成森林
    3. 遍历序列不一定唯一
    4. 适合寻找路径、判断连通性等问题
    5. 非连通图需要多次 DFS 才能遍历全部顶点

    <Warning>
    DFS 递归深度最坏为 $O(n)$（单链状图），空间复杂度也为 $O(n)$；不要只记时间复杂度。
    </Warning>
  </Accordion>

  <Accordion title="BFS 与 DFS 对比">
    | 比较项目 | BFS | DFS |
    | --- | --- | --- |
    | 数据结构 | 队列 | 栈或递归 |
    | 搜索方式 | 逐层向外扩展 | 沿路径深入 |
    | 是否回溯 | 不需要 | 需要 |
    | 无权图最短路径 | 可以 | 不保证 |
    | 生成结构 | BFS 生成树/森林 | DFS 生成树/森林 |
    | 邻接矩阵时间复杂度 | $O(n^2)$ | $O(n^2)$ |
    | 邻接表时间复杂度 | $O(n+m)$ | $O(n+m)$ |

    <Tip>
    **记忆**：BFS 像“水波扩散”，DFS 像“走迷宫”。求无权最短路用 BFS，判断连通性两者都可以。
    </Tip>
  </Accordion>

  <Accordion title="遍历与连通性">
    **无向图**：

    从每个未访问顶点启动一次完整的 BFS 或 DFS：

    - 一次遍历能访问到的顶点属于同一个连通分量
    - 所有顶点都被访问，则图连通
    - 还有顶点未访问，则重新选择起点继续遍历

    **连通分量个数 = 完整遍历的启动次数。**

    **有向图**：

    - 可以判断顶点之间的可达性
    - 弱连通不等于强连通
    - 一次遍历访问到全部顶点，不能直接说明强连通
    - 判断强连通性需要检查任意两个顶点是否相互可达

    **生成树与生成森林**：

    - 连通图的一次 BFS/DFS 得到一棵生成树
    - 非连通图得到生成森林
    - BFS 生成树的高度等于源点到各顶点的最短路径长度（无权图）

    ```c 遍历非连通图
    void Traverse(Graph G) {
        for (int i = 0; i < G.vexnum; i++)
            visited[i] = false;

        for (int i = 0; i < G.vexnum; i++)
            if (!visited[i])
                BFS(G, i);   // 或 DFS(G, i)
    }
    ```
  </Accordion>
</AccordionGroup>

## 最小生成树

最小生成树是带权连通无向图中权值之和最小的生成树，常用 Prim 和 Kruskal 两种贪心算法。

<AccordionGroup>
  <Accordion title="定义与性质">
    **最小生成树（MST）**：带权连通无向图中，权值之和最小的生成树。

    性质：

    1. 包含全部 $n$ 个顶点
    2. 有 $n-1$ 条边
    3. 不存在回路
    4. 权值之和最小
    5. 最小生成树不一定唯一

    <Warning>
    最小生成树只针对**连通带权无向图**。若图不连通，只能求每个连通分量的最小生成树，得到最小生成森林。
    </Warning>

    **唯一性**：

    - 所有边权值互不相同时，最小生成树一定唯一
    - 存在相同权值时，最小生成树仍可能唯一

    ```mermaid
    graph LR
      A["A"] ---|1| B["B"]
      A ---|3| C["C"]
      B ---|2| C
      B ---|4| D["D"]
      C ---|5| D
      linkStyle 0,2,3 stroke:#BD5B3D,stroke-width:3px
    ```

    粗边表示一种最小生成树：AB、BC、BD，权值和为 $1+2+4=7$。

    <Tip>
    MST 的两种经典算法都基于贪心：Prim 从“顶点集合”扩展，Kruskal 从“边集合”选择。
    </Tip>
  </Accordion>

  <Accordion title="Prim 算法">
    从任意一个顶点开始，每次选择一条连接“已选顶点集合 $U$”和“未选顶点集合 $V-U$”的最小权值边，把新顶点加入 $U$。

    **基本步骤**：

    1. 任选一个顶点作为起点，加入 $U$
    2. 找到连接 $U$ 与 $V-U$ 的最小权值边
    3. 把该边和新顶点加入生成树
    4. 重复直到所有顶点都加入

    **复杂度**：

    $$
    O(n^2)
    $$

    通常采用邻接矩阵和数组实现。

    - 适合**稠密图**
    - 起点任意，得到的最小生成树权值相同
    - 与 Dijkstra 形式相似，但 Prim 维护的是“到已选集合的最短边”，Dijkstra 维护的是“到源点的最短距离”

    <Warning>
    Prim 与 Dijkstra 的更新对象容易混淆：Prim 更新的是“顶点到当前生成树集合的最小边权”，Dijkstra 更新的是“顶点到源点的最短距离”。
    </Warning>
  </Accordion>

  <Accordion title="Kruskal 算法">
    把所有边按权值从小到大排序，每次选择当前权值最小且**不会形成回路**的边，直到选出 $n-1$ 条边。

    **基本步骤**：

    1. 所有边按权值升序排序
    2. 依次取出权值最小的边
    3. 用并查集判断加入后是否形成回路
    4. 不形成回路则加入生成树，并合并两个集合
    5. 形成回路则舍弃
    6. 选够 $n-1$ 条边时停止

    **并查集判断**：

    - 两个端点属于不同集合：可以加入，合并集合
    - 两个端点属于同一集合：加入会成环，舍弃

    **复杂度**：

    $$
    O(m\log m)
    $$

    主要来自边的排序。

    - 适合**稀疏图**
    - 需要能方便地取出所有边
    - 边权相同时，选择顺序可能不同，因此 MST 可能不唯一

    <Tip>
    Kruskal 的“是否成环”判断是并查集的典型应用：同集合成环，不同集合可合并。
    </Tip>
  </Accordion>

  <Accordion title="Prim 与 Kruskal 对比">
    | 比较项目 | Prim | Kruskal |
    | --- | --- | --- |
    | 核心思想 | 从顶点集合扩展 | 从边集合选择 |
    | 选择依据 | 连接内外顶点的最小边 | 当前最小且不构成环的边 |
    | 是否需要排序全部边 | 不需要 | 需要 |
    | 判断环 | 不需要显式使用并查集 | 通常使用并查集 |
    | 时间复杂度 | $O(n^2)$ | $O(m\log m)$ |
    | 适用图 | 稠密图 | 稀疏图 |

    <Check>
    **选择**：边多、$n$ 较小 → Prim；边少、$m$ 较小 → Kruskal。
    </Check>
  </Accordion>
</AccordionGroup>

## 最短路径

最短路径分为单源最短路径（Dijkstra）和多源最短路径（Floyd）两类。

<AccordionGroup>
  <Accordion title="Dijkstra 算法">
    求一个指定源点到其他所有顶点的最短路径。

    **适用条件**：图中不存在负权边。

    **核心思想**：每次从尚未确定最短路径的顶点中，选择当前距离源点最近的顶点，确定其最短路径，再用它更新其他顶点的距离。

    **基本步骤**：

    1. 初始化距离数组 `dist`
    2. 源点到自身距离为 0
    3. 源点到其他顶点初始化为直接边权值，不存在直接边则为 $\infty$
    4. 选择未确定顶点中 `dist` 最小的顶点 $v$
    5. 标记 $v$ 已确定
    6. 用 $v$ 更新其他未确定顶点的距离
    7. 重复直到所有可达顶点确定

    **距离更新**：

    $$
    dist[w]=\min\big(dist[w],\ dist[v]+w_{vw}\big)
    $$

    其中 $w_{vw}$ 是 $v$ 到 $w$ 的边权。

    **复杂度**：

    $$
    O(n^2)
    $$

    按邻接矩阵和数组实现。

    - 单源最短路径
    - 不能处理负权边
    - 每次选择当前距离源点最近的未确定顶点
    - 一旦某顶点被确定，其最短距离不再改变（非负权前提下）
    - 可以用 `pre[]` 数组记录前驱，回溯得到路径

    <Warning>
    Dijkstra 不能处理负权边。若存在负权边，已经确定的顶点可能被后续的负边“变得更短”，贪心前提被破坏。
    </Warning>
  </Accordion>

  <Accordion title="Floyd 算法">
    求图中任意两个顶点之间的最短路径，也叫多源最短路径。

    **核心思想**：逐步考虑每个顶点能否作为中间顶点，使两个顶点之间的路径变短。

    设 $D^{(k)}[i][j]$ 表示从 $i$ 到 $j$、允许使用前 $k$ 个顶点作为中间顶点时的最短距离：

    $$
    D^{(k)}[i][j]=\min\left\{D^{(k-1)}[i][j],\ D^{(k-1)}[i][k]+D^{(k-1)}[k][j]\right\}
    $$

    去掉上标，写成三重循环中的更新：

    $$
    D[i][j]=\min\big(D[i][j],\ D[i][k]+D[k][j]\big)
    $$

    **初始化**：

    - 对角线 $D[i][i]=0$
    - 有直接边则填边权
    - 没有直接边则填 $\infty$

    **复杂度**：

    - 时间复杂度 $O(n^3)$
    - 空间复杂度 $O(n^2)$

    - 可以处理负权边
    - 不能存在负权回路
    - 属于动态规划思想
    - 可以用 `path[i][j]` 记录中间结点，回溯得到路径

    <Warning>
    Floyd 的三重循环中，**中间顶点 $k$ 必须放在最外层**。若把 $i$ 或 $j$ 放在最外层，状态转移的依赖顺序会被破坏，结果可能错误。
    </Warning>
  </Accordion>

  <Accordion title="Dijkstra 与 Floyd 对比">
    | 比较项目 | Dijkstra | Floyd |
    | --- | --- | --- |
    | 求解问题 | 单源最短路径 | 多源最短路径 |
    | 适用范围 | 所有边非负 | 可以有负权边 |
    | 时间复杂度 | $O(n^2)$ | $O(n^3)$ |
    | 空间复杂度 | $O(n^2)$（矩阵） | $O(n^2)$ |
    | 核心思想 | 贪心 | 动态规划 |
    | 负权回路 | 不适用 | 不允许 |

    <Tip>
    **记忆**：Dijkstra 是“一个源点，贪心扩展”；Floyd 是“任意两点，枚举中间点”。
    </Tip>
  </Accordion>
</AccordionGroup>

## 有向无环图与拓扑排序

<AccordionGroup>
  <Accordion title="DAG 描述表达式">
    **DAG（有向无环图）**：不存在有向环的有向图。

    DAG 可以描述表达式中的运算关系：

    - 顶点表示操作数或运算符
    - 有向边表示运算之间的依赖关系
    - 相同的子表达式可以共用同一个顶点，避免重复计算

    <Info>
    DAG 的核心价值是**共享公共子表达式**：同一个子表达式只计算一次，后续运算直接引用它的结果，从而减少重复计算。
    </Info>

    <Tip>
    DAG 与表达式树的区别：表达式树中相同子表达式会出现多个副本；DAG 允许同一个子表达式结点被多个父结点共享。
    </Tip>
  </Accordion>

  <Accordion title="拓扑排序">
    **拓扑排序**：对有向无环图（DAG）的顶点进行线性排列，使得对每条弧 $v_i\rightarrow v_j$，在序列中 $v_i$ 都排在 $v_j$ 之前。

    ```mermaid
    graph LR
      v1["v1"] --> v2["v2"]
      v1 --> v3["v3"]
      v2 --> v4["v4"]
      v3 --> v4
      v4 --> v5["v5"]
    ```

    当所有弧都从左指向右时，从左到右的顶点顺序就是一个拓扑序列。

    **基本步骤**（入度数组 + 栈/队列）：

    1. 计算所有顶点的入度
    2. 所有入度为 0 的顶点入栈
    3. 栈非空时，弹出一个顶点并输出
    4. 删除该顶点的所有出边
    5. 这些边指向的顶点入度减 1
    6. 入度变为 0 的顶点入栈
    7. 重复直到栈为空

    ```c 拓扑排序
    bool TopologicalSort(Graph G) {
        InitStack(S);
        for (int i = 0; i < G.vexnum; i++)
            if (indegree[i] == 0)
                Push(S, i);

        int count = 0;
        while (!IsEmpty(S)) {
            Pop(S, i);
            print[i];
            count++;

            for (ArcNode *p = G.vertices[i].firstarc; p; p = p->nextarc) {
                int v = p->adjvex;
                if (--indegree[v] == 0)
                    Push(S, v);
            }
        }
        return count == G.vexnum;
    }
    ```

    **判断有向图是否存在环**：

    - 输出顶点数 $=n$：无环，是 DAG
    - 输出顶点数 $<n$：存在有向环

    **重要性质**：

    1. 只有 DAG 才存在拓扑排序
    2. 拓扑排序结果不一定唯一
    3. DAG 一定至少有一个入度为 0 的顶点
    4. 所有顶点都能被输出，则一定不存在有向环
    5. DAG 至少有一个拓扑排序序列
    6. 若每一步都只有一个入度为 0 的顶点，则拓扑序列唯一

    | 存储结构 | 时间复杂度 |
    | --- | --- |
    | 邻接表 | $O(n+m)$ |
    | 邻接矩阵 | $O(n^2)$ |

    <Tip>
    拓扑排序用栈还是队列都可以，得到的序列可能不同，但都合法。
    </Tip>
  </Accordion>
</AccordionGroup>

## 关键路径

关键路径用于估算工程的最短完成时间，核心是求事件的 $ve$、$vl$ 和活动的 $e$、$l$。

<AccordionGroup>
  <Accordion title="AOE 网与 AOV 网">
    **AOE 网（Activity On Edge）**：边表示活动的网络。

    - 顶点表示事件
    - 有向边表示活动
    - 边权表示活动持续时间
    - 源点表示工程开始
    - 汇点表示工程完成

    **AOV 网（Activity On Vertex）**：顶点表示活动的网络，边表示活动之间的优先关系。

    | 比较项目 | AOV 网 | AOE 网 |
    | --- | --- | --- |
    | 顶点表示 | 活动 | 事件 |
    | 边表示 | 活动之间的优先关系 | 活动及其持续时间 |
    | 主要用途 | 拓扑排序 | 关键路径 |

    ```mermaid
    graph LR
      v1["v1"] -->|3| v2["v2"]
      v1 -->|2| v3["v3"]
      v2 -->|2| v4["v4"]
      v3 -->|4| v4
      v4 -->|3| v5["v5"]
    ```

    上图是 AOE 网示意：$v_1$ 为源点，$v_5$ 为汇点，边上的数字为活动持续时间。

    <Tip>
    **记忆**：AOV 是“点是活动”，AOE 是“边是活动”。关键路径只在 AOE 网中讨论。
    </Tip>
  </Accordion>

  <Accordion title="四个时间量">
    | 符号 | 名称 | 含义 |
    | --- | --- | --- |
    | $ve(j)$ | 事件最早发生时间 | 事件 $j$ 最早可以发生的时间 |
    | $vl(j)$ | 事件最迟发生时间 | 不延误整个工程的前提下，事件 $j$ 最迟发生的时间 |
    | $e(i)$ | 活动最早开始时间 | 活动 $i$ 最早可以开始的时间 |
    | $l(i)$ | 活动最迟开始时间 | 不延误整个工程，活动 $i$ 最迟可以开始的时间 |

    **事件最早发生时间**：从源点开始，按拓扑顺序计算。

    设源点为 $s$、汇点为 $t$：

    $$
    ve(s)=0
    $$

    $$
    ve(j)=\max_{i\rightarrow j}\{ve(i)+w(i,j)\}
    $$

    事件 $j$ 要等所有前置活动完成，所以取最大值。

    **事件最迟发生时间**：从汇点开始，按逆拓扑顺序计算。

    $$
    vl(t)=ve(t)
    $$

    $$
    vl(i)=\min_{i\rightarrow j}\{vl(j)-w(i,j)\}
    $$

    当前事件必须保证后续所有活动都能按时完成，所以取最小值。

    **活动时间**：设活动对应弧 $j\rightarrow k$：

    $$
    e(i)=ve(j)
    $$

    $$
    l(i)=vl(k)-w(j,k)
    $$

    **关键活动**：

    $$
    e(i)=l(i)
    $$

    活动时间余量：

    $$
    d(i)=l(i)-e(i)
    $$

    - $d(i)=0$：关键活动
    - $d(i)>0$：非关键活动

    <Warning>
    $ve$ 用 $\max$，$vl$ 用 $\min$；$e(i)$ 取弧尾事件的 $ve$，$l(i)$ 取弧头事件的 $vl$ 减去活动持续时间。不要把 $e$ 和 $l$ 的端点弄反。
    </Warning>
  </Accordion>

  <Accordion title="关键路径的计算步骤">
    1. 对 AOE 网进行拓扑排序，得到拓扑序列
    2. 按拓扑顺序求 $ve$：从源点向汇点，取最大值
    3. 按逆拓扑顺序求 $vl$：从汇点向源点，取最小值
    4. 求活动最早开始时间 $e(i)=ve(j)$
    5. 求活动最迟开始时间 $l(i)=vl(k)-w(j,k)$
    6. 满足 $e(i)=l(i)$ 的活动为关键活动
    7. 从源点到汇点由关键活动组成的路径为关键路径

    <Check>
    **关键路径长度** = 整个工程的最短完成时间。关键路径是 AOE 网中从源点到汇点的**最长路径**。
    </Check>
  </Accordion>

  <Accordion title="关键路径的性质">
    1. 关键路径是 AOE 网中从源点到汇点的最长路径
    2. 关键路径的长度等于整个工程的最短完成时间
    3. 一个 AOE 网可能存在多条关键路径
    4. 关键活动的时间余量为 0
    5. 缩短关键活动的持续时间，才可能缩短整个工程工期
    6. 非关键活动可以在时间余量范围内延迟，不影响总工期
    7. 关键路径可能发生改变

    <Warning>
    如果存在多条关键路径，仅缩短其中一条关键路径上的某项活动，**不一定**能缩短整个工程的完成时间；只有缩短同时位于所有关键路径上的活动，才能稳定缩短工期。
    </Warning>
  </Accordion>
</AccordionGroup>

## 算法对比与公式汇总

<AccordionGroup>
  <Accordion title="遍历与生成树算法">
    | 算法 | 数据结构 | 主要用途 | 时间复杂度 |
    | --- | --- | --- | --- |
    | BFS | 队列 | 广度优先遍历、无权最短路径 | $O(n+m)$（邻接表） |
    | DFS | 栈/递归 | 深度优先遍历、连通性 | $O(n+m)$（邻接表） |
    | Prim | 数组等 | 最小生成树 | $O(n^2)$ |
    | Kruskal | 排序 + 并查集 | 最小生成树 | $O(m\log m)$ |

    <Info>
    BFS/DFS 的时间复杂度取决于存储结构：邻接矩阵为 $O(n^2)$，邻接表为 $O(n+m)$。
    </Info>
  </Accordion>

  <Accordion title="最短路径、拓扑排序与关键路径">
    | 算法 | 主要用途 | 核心思想 | 时间复杂度 |
    | --- | --- | --- | --- |
    | Dijkstra | 单源最短路径 | 贪心 | $O(n^2)$ |
    | Floyd | 多源最短路径 | 动态规划 | $O(n^3)$ |
    | 拓扑排序 | 判断 DAG、任务排序 | 入度为 0 的顶点优先 | $O(n+m)$ |
    | 关键路径 | 求工程最短完成时间 | 正向取最大、反向取最小 | $O(n+m)$ |

    <Tip>
    Dijkstra 的 $O(n^2)$ 按常规邻接矩阵实现；Floyd 的空间为 $O(n^2)$；拓扑排序和关键路径按邻接表实现为 $O(n+m)$。
    </Tip>
  </Accordion>

  <Accordion title="基本公式">
    **度与边数**：

    $$
    \sum_{v\in V}TD(v)=2m
    $$

    $$
    \sum_{v\in V}ID(v)=\sum_{v\in V}OD(v)=m
    $$

    **完全图**：

    - 无向完全图：$m=\dfrac{n(n-1)}{2}$
    - 有向完全图：$m=n(n-1)$

    **生成树**：

    $$
    m=n-1
    $$

    **最短路径**：

    $$
    dist[w]=\min(dist[w],dist[v]+w_{vw})
    $$

    $$
    D[i][j]=\min(D[i][j],D[i][k]+D[k][j])
    $$

    **关键路径**：

    $$
    ve(j)=\max_{i\rightarrow j}\{ve(i)+w(i,j)\}
    $$

    $$
    vl(i)=\min_{i\rightarrow j}\{vl(j)-w(i,j)\}
    $$

    $$
    e(i)=ve(j),\qquad l(i)=vl(k)-w(j,k)
    $$

    关键活动满足 $e(i)=l(i)$。

    $$
    d(i)=l(i)-e(i)
    $$
  </Accordion>
</AccordionGroup>

<AccordionGroup>
  <Accordion title="结论判断易错清单">
    | 知识点 | 正确结论 |
    | --- | --- |
    | 无向图度数总和 | $2m$ |
    | 有向图入度总和 | $m$ |

    | 生成树边数 | $n-1$ |
    | 生成森林 | 非连通图各连通分量的生成树组成 |
    | 无向图邻接矩阵 | 对称矩阵 |
    | 无向图邻接表 | 每条边存两次 |
    | 有向图邻接表 | 每条边通常存一次 |
    | 十字链表 | 有向图 |
    | 邻接多重表 | 无向图 |
    | BFS | 队列 |
    | DFS | 栈或递归 |
    | BFS 无权最短路径 | 可以 |
    | DFS 无权最短路径 | 不保证 |
    | Prim | 连接已选与未选顶点的最小边 |
    | Kruskal | 按边权排序，避免形成回路 |
    | Dijkstra | 不能处理负权边 |
    | Floyd | 可以处理负权边，但不能存在负权回路 |
    | 拓扑排序 | 只适用于 DAG |
    | 拓扑序列 | 不一定唯一 |
    | AOV 网 | 顶点表示活动 |
    | AOE 网 | 边表示活动 |
    | 关键活动 | $e(i)=l(i)$ |
    | 关键路径 | AOE 网中源点到汇点的最长路径 |
  </Accordion>

  <Accordion title="三个易混概念">
    | 概念 | 顶点 | 边 | 关键条件 |
    | --- | --- | --- | --- |
    | 生成子图 | 保留全部顶点 | 可以删除部分边 | 不要求连通、不要求无环 |
    | 生成树 | 保留全部顶点 | 恰好 $n-1$ 条边 | 连通且无环 |
    | 生成森林 | 保留全部顶点 | 每个连通分量 $n_i-1$ 条边 | 各连通分量分别无环 |

    <Warning>
    **生成子图不是生成树**：生成子图只要求 $V'=V$；生成树还要求连通且无环。不要看到“包含全部顶点”就选生成树。
    </Warning>
